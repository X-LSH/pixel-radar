# Pixel Radar · 像素航班雷达

**线上：<https://x-lsh.github.io/pixel-radar/>**

打开浏览器，看到一块老式像素雷达屏：以机场为中心，实时显示周边空域的
飞机起降、巡航与盘旋，带尾迹、扫描线、可点击信息卡。

**零后端 · 零构建 · 零依赖 · 零密钥。** 源码直接放仓库根目录即上线。

> 打开就有一片真实空域（默认北京首都）。数据由 GitHub Actions 定时采集写入
> `data` 分支，前端并行竞速读取三个镜像 —— **定时任务会被 GitHub 大量丢弃**
> （实测 `*/5` 六天只触发 41 次，已加错峰 cron 缓解），页面状态栏始终显示
> 快照的实际年龄（如「更新 14 分前」），陈旧从不被隐藏。

## 快速开始

```bash
node scripts/serve.mjs              # 起本地服务（无依赖，无需 npm install）
# 打开 http://127.0.0.1:5173/

node scripts/collect.mjs            # 可选：采集 20 个机场的真实 ADS-B 快照
node scripts/collect.mjs --icao=ZBAA,ZSPD,VHHH
node scripts/collect.mjs --watch=300   # 常驻，每 5 分钟刷新，本地也能看到「准实时」
```

其它命令：

| 命令 | 作用 |
|---|---|
| `npm run verify` | 不变量自检（204 项，纯逻辑，不开浏览器） |
| `npm run e2e` | 真实 Chrome 端到端验证（40 项，含真实鼠标/键盘事件 + 截图） |
| `BASE=<url> REQUIRE_REAL=1 npm run e2e` | 对线上地址验证，并**强制要求数据是真实的**（拒绝模拟兜底；43 项） |
| `npm run build:data` | 重建机场 / 跑道 / 海岸线 / 建成区数据（需联网，上游原件会缓存到 `.tmp/raw/`） |

## ⚠️ 数据源现状（2026-09 实测，这一节决定了整个架构）

规格原案是「零后端 + 浏览器直连免费 ADS-B API + 5 秒轮询」。
**实测这条路在 2026 年 9 月已经走不通**，证据如下：

| 数据源 | 连通性 | 数据质量 | `Access-Control-Allow-Origin` | 结论 |
|---|---|---|---|---|
| `airplanes.live` | ❌ HTTP 403 | — | — | 已封，现要求邮件申请白名单 |
| `adsb.lol` | ✅ 200 | ⭐ 极佳（含 `track_rate`/`roll`/`mach`） | **无此响应头** | 有数据，但浏览器读不到 |
| OpenSky | ✅ 200 | 一般 | `https://opensky-network.org`（只允许自身） | 跨域被拒 |
| `adsb.fi` | ❌ 404 | — | — | 不可用（端点已废） |
| `adsb.one` | ❌ 403 | — | — | 需邮件注册白名单 |
| `adsbdb.com`（航班/航司元数据） | ✅ 200 | 好 | ✅ `*` | **可用** |
| `hexdb.io`（机型/注册号元数据） | ✅ 200 | 好 | ✅ `*` | **可用** |

两个验证步骤，确保这不是观测误差：

1. **阳性对照**：用同一条网络通路请求 `api.github.com`，其
   `Access-Control-Allow-Origin: *` 完整返回 → 证明不是本地代理吞了响应头。
2. **旁证**：真实开源雷达项目 `AeroStream` 的 README 明写
   *"ProxyServer.js is used to run the website's proxy for API to deal with CORS restrictions from ADSB.lol"*。

公共 CORS 中转也一并塌了：`corsproxy.io` 现在要 API Key（401），
`allorigins` / `codetabs` 均无响应。

### 因此采用的方案：四层降级

```
自备中继  →  静态快照  →  直接聚合源  →  模拟数据
（可选）     （默认通路）   （预期失败）    （永不空屏）
```

**静态快照是默认通路。** `scripts/collect.mjs` 在服务端（Node / GitHub Actions
的 runner 没有同源策略限制）定期取数并落成静态 JSON，前端**并行竞速**读取三份镜像：

- `raw.githubusercontent.com` —— 官方直读，带 `ACAO: *`、缓存 5 分钟，与采集节奏吻合；
- `cdn.jsdelivr.net` / `ghproxy.net` —— 国内可达的备援（raw 被墙时的救命通道）。

首个响应回来后再等 600ms 择优窗口，按 `fetchedAt` 取最新的一份；404 的候选会被
判死、后续周期不再请求。仓库名由 `location` 运行时推断，推断不出（localhost 等）
时用内置 `fallbackRepo` 直读同一 `data` 分支 —— **本地开发零配置即有真实数据**，
本地 `data/snapshots` 若更新鲜则优先采用。这样绕开了 CORS，保住了「零后端」。

**为什么快照放在独立的 `data` 分支**：`main` 上每次推送都会触发一次
GitHub Pages 构建，而快照计划每 5 分钟更新一次，一天 288 次会把 legacy 构建的
配额（10 次/小时）顶穿。`data` 分支不参与 Pages，前端经上述镜像直读。

**想要真·5 秒实时？** 在侧栏「自定义中继地址」填入一个你自建的转发地址
（Cloudflare Worker 约 30 行即可）就能恢复实时，无需改代码：

```
GET {你的中继}?lat=<lat>&lon=<lon>&nm=<半径海里>
→ 返回上游原始 JSON（含 ac 数组）或 { planes: [...] } 或裸数组
```

### 上游的两个坑（已固化进采集脚本）

1. **静默限流**：`adsb.lol` 在轻度过载时**不返回错误码**，而是
   HTTP 200 + 空 `ac` 数组（`{"ac":[],"msg":"No error","total":0}`）。
   这与「该空域真的没有接收站覆盖」在响应上完全无法区分。
   → 采集脚本收到空结果会等 6 秒复核一次，两次都空才认定是覆盖缺口；
   默认请求间隔也从 1.1 秒放宽到 2 秒。
2. **覆盖不均**：实测同一时刻北京周边有 13.5KB 目标，而上海浦东
   （50nm 半径内）`total: 0` —— 是该区域在上游网络中确实缺少接收站。
   → 采集端的三层取数链 `adsb.lol → airplanes.live → OpenSky bbox` 会逐层换源
   复核，末尾再对「出错 / 为空」的机场补采两轮（限流 403 通常半分钟后自愈）；
   三层皆空才定稿为覆盖缺口。前端把「空结果」按无数据处理并继续降级，
   由界面明确标注来源，绝不用一块空白雷达屏糊弄过去。

   一次真实采集的覆盖分布（2026-09-17 04:46 UTC，20 个预设机场）：

   | 机场 | 架数 | | 机场 | 架数 |
   |---|---|---|---|---|
   | KLAX | 73 | | ZGSZ | 38 |
   | RJTT | 64 | | OMDB | 38 |
   | YMML | 63 | | EDDF | 36 |
   | KSEA | 61 | | LFPG | 28 |
   | RJAA | 60 | | ZBAA | 21 |
   | KSFO | 57 | | WSSS | 13 |
   | YSSY | 50 | | ZGGG | 5 |
   | EGLL | 47 | | **ZSPD** | **0** ← 无接收覆盖 |
   | KJFK | 47 | | **ZUUU** | **0** ← 无接收覆盖 |
   | RKSI | 40 | | VHHH | 39 |

   **18 / 20 有真实数据。** 上海浦东与成都双流在三层上游（含 OpenSky）中
   均无数据，属真实覆盖缺口，这两个机场会明确回落到模拟数据并在屏角标注
   「模拟数据」。

### 几个关键设计取舍

**逻辑分辨率不固定为 480×360，而是「锁定整数倍像素尺寸、反推逻辑分辨率」。**
任意宽高比都能铺满且永远没有半像素；用 `Math.ceil` 保证画布至少覆盖视口，
多出的不到 1 个像素由父容器裁掉。

**投影用局部等距方位投影（AEQD），而不是 Web Mercator。**
墨卡托只保角不保距，在 50km 尺度上距离环会被拉成椭圆 ——
而距离环是本项目最核心的视觉语言。AEQD 的中心固定在**机场**而非视口中心，
所以平移时圆环依然是真圆（这也是真实雷达的语义：天线在机场）。

**底图画得比视口大一圈（四周各留 40% 边距），平移只改 blit 偏移。**
否则拖动地图会每帧重算四五千个投影点，直接掉到个位数帧率。
平移范围由地景数据的裁剪半径反推，绝不会拖到一片空白。

**飞机精灵预渲染 16 个方位。** 规格要求如此，也确实必须如此：
canvas 的 `rotate() + drawImage` 会对 12×12 位图做双线性重采样，
在整数倍放大后就是一团灰边。按方位重采样一次得到的是纯 1bit 像素。

**建成区用网点纹理而不是实心填充。** 实心块在城市密集区会变成一整片抢戏的
亮绿（实测北京与纽约都把大半屏糊掉了，网格与海岸线全被压住）；
网点既压住了亮度，又自带像素画的颗粒感，网格还能从孔洞里透出来。

**HUD 屏内只出现 ASCII。** 这是 CRT 字符发生器的真实能力边界，
换来的好处是任何分辨率下文字都是硬边像素。中文界面文案全部放在 DOM 外壳里。

**信息卡的缺失字段显示「—」并说明来源，绝不用 0 假装有值。**
「0 英尺」和「没有高度数据」是两件事。国别优先用上游字段，
缺失时按 ICAO24 地址块推断，并在卡上标注「国别按地址块推断」；
两者都不可得就显示「—」，不编一个国家出来。

## 数据来源与许可

| 数据 | 来源 | 许可 |
|---|---|---|
| 航班位置 | [adsb.lol](https://adsb.lol) | ODbL |
| 机场坐标、跑道端点/朝向/长度 | [OurAirports](https://ourairports.com/data/) | Public Domain |
| 海岸线、城市建成区、湖泊 | [Natural Earth](https://www.naturalearthdata.com/) 1:10m | Public Domain |
| 机型 / 注册号（可选元数据） | [hexdb.io](https://hexdb.io)、[adsbdb.com](https://www.adsbdb.com) | 见各自站点 |

滑行道与停机坪是**由跑道几何派生的示意图形**，并非真实设施数据，
因此只在放大到一定程度时出现，也不在界面上伪装成精确设施。
